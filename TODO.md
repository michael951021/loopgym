## Sandbox server: lgbox (Rust)

Each run: fresh temp dir, child in its own process group with setrlimit (RLIMIT_AS = mem_mb, RLIMIT_CPU = timeout+1, RLIMIT_NPROC 64, RLIMIT_FSIZE 16 MB), stdin null, killpg on timeout, temp dir removed after. ## Kernel: fused token log-probs
> why: GRPO needs log-probs of every sampled token over a 152k vocab; materialising [T, V] logits dominates memory. A chunked fused kernel (torch, C++, Triton, CUDA) keeps memory O(T·chunk) and is the C++/CUDA work in the project.
- [x] **Torch chunked log-probs** — loopgym/kernels/__init__.py: `IMPLS` tuple and `token_logprobs(hidden, weight, targets, impl="torch", chunk=8192)` → float32 [T]; "torch" = loop over V in chunks with an online max/log-sum-exp, a custom autograd.Function whose backward recomputes each chunk's softmax (no [T, V] tensor saved). Done when `LOOPGYM_KNOWN_STRICT=1 .venv/bin/python -m pytest -q tests/known/test_logprob.py` passes (needs models/). (id: kernelpy) (after: models)
  why: the reference fused implementation; every faster one must match it and the known tests.
- [x] **C++ CPU kernel forward** — csrc/logprob_cpu.cpp: torch C++ extension built with torch.utils.cpp_extension.load (JIT, build dir .tools/build, `-O3 -fopenmp`), OpenMP over T, per row a single pass over V in chunks (online max and sum, dot products via at::matmul per chunk or a blocked loop); registers impl "cpp" in kernels.IMPLS when it builds. Done when `LOOPGYM_KNOWN_STRICT=1 .venv/bin/python -m pytest -q tests/known/test_logprob.py -k "cpp and not gradient"` passes. (id: cppfwd) (after: kernelpy)
  why: the C++ half of the kernel work, testable on CPU against Kevin's tests.
- [x] **C++ CPU kernel backward** — logprob_cpu.cpp backward w.r.t. hidden: grad_h[t] = g[t]·(W[target[t]] − Σ_v softmax_v W[v]), recomputed per chunk from the saved per-row log-sum-exp; wired into an autograd.Function. Done when `LOOPGYM_KNOWN_STRICT=1 .venv/bin/python -m pytest -q tests/known/test_logprob.py -k cpp` passes (gradcheck included). (id: cppbwd) (after: cppfwd)
  why: training needs gradients through the kernel; gradcheck in float64 is the known answer.
- [x] **Triton kernel (interpreter tested)** — loopgym/kernels/triton_logprob.py forward + backward (tiles over V, online softmax), registered as "triton" when CUDA is present or TRITON_INTERPRET=1; add triton to pyproject.
