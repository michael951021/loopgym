# Fix grpo05: OOM (ran out of memory)

## Issue
Compute job `grpo05` was OOM-killed — it exceeded its 39.0 GB memory cap (systemd MemoryMax), so every ticket waiting on its results is blocked. It peaked at ~30.8 GB (systemd MemoryPeak) against the 39.0 GB cap — well under the cap, so this is likely a transient spike or a runaway in one step, not a steady need. Fixable: either cut the peak memory (e.g. micro-batch so a full [rows, T, vocab] tensor is never held, or run each arm/stage in its own process so memory is released between them) or raise the job line's `(mem:)` cap if the peak is genuinely needed.
